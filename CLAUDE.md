# Skyrome — agent guide

Skyrome is a non-linear, Skyrim-style open-world action RPG set in Rome in AD 113, under Trajan. It runs in the browser on TypeScript, Three.js r186, Rapier 0.21 (WASM physics) and Vite 8. Everything is procedural: architecture, characters, textures and audio are generated in code or come from CC0 sources. The owner is new to game development. AI agents do most of the building.

Design docs: `docs/STORY.md` (the story as played: Act I chapter by chapter, and the rules the story keeps; it wins over the other docs where they differ), `docs/GDD.md` (game design), `docs/CONTENT.md` (NPCs, quests, items), `docs/ATLAS.md` with `src/data/atlas.ts` (historical map data), `docs/ARCHITECTURE.md` (code structure), and `docs/research/` (background research).

## Commands
- `npm run dev`: dev server on http://127.0.0.1:5173. Pick a scene with `?scene=<name>` (files in `src/scenes/`) and turn on the stats overlay with `?debug`. The console's `tdo` command toggles the overlay too.
- `npm test`: Vitest, for pure logic in `tests/` and `src/**/*.test.ts`.
- `npm run typecheck`: `tsc --noEmit`. It must stay clean.
- `npm run build`: typecheck plus a production build into `dist/`.
- `npm run check:controls`: drives the real game with real keyboard events in Chromium and WebKit, for all three control presets (mouse, trackpad, keyboard). It checks movement, camera, combat, talking, menus, stuck keys, the hotbar, saves and saved-binding repair. Run it after touching input, UI key handling, the player controller, the camera, combat input or the game flow. Use `--only "name,name"` to run single checks.
- `node scripts/perf.mjs [--views spawn,forum,circus,cavea,colosseum,pantheon] [--size 1512x860 --dpr 2]`: performance survey. For each viewpoint it reports the frame rate and CPU ms (mean and p95), GPU ms (timer queries), draw calls and triangles looking four ways, CPU per system, and memory. Run it before and after performance work and compare. `--size 1512x860 --dpr 2` approximates the owner's MacBook.
- `node scripts/perf-budget.mjs [--views forum,colosseum] [--graphics high|medium] [--repeat 2]`: the performance gate. It boots fixed views and fails when CPU (mean, p95), render submit, draw calls, triangles, slow frames (> 33 ms) or boot time exceed `scripts/perf-budget.json`, or when menus and the title draw too much. Run it before handing in work that changes what is drawn or done every frame; `--write-budget` resets the budgets (say why). Probes for digging in: `scripts/perf-probe.mjs` (render submit by step, A/B switches in one page, `--glcount`, `--cpuprofile --pan`), `scripts/perf-gc.mjs` (GCs per minute, allocations by function), `scripts/perf-boot.mjs` (boot phases, `--profile`). Method and numbers: `docs/research/perf-audit-2026-10.md`.
- `node scripts/soak.mjs [--minutes 30] [--home 90]`: AC-20 soak. A bot wanders, fights and saves/loads for N minutes; it fails on a crash, a page error or more than 100 MB of heap growth after warm-up (it forces a real GC before each sample and logs geometry/collider counts).
- `node scripts/leaks.mjs [--phases teleport,interior,saveload,menus,fights,idle,daynight,munus,soak] [--scale 0.2] [--orphans]`: leak harness (docs/research/memory-audit-2026-10.md). Runs cycles of one activity at a time with a forced GC and a full set of counters after each (heap, renderer geometries/textures, Rapier colliders, live AudioNodes, DOM, listeners, timers) and exits 1 when a phase keeps growing. Run it after touching caches, disposal, streaming or anything that creates geometry per NPC or fight. `scripts/heap-summary.mjs` (who holds the big arrays in a `.heapsnapshot`), `scripts/heap-sites.mjs` and `scripts/leaks-probe.mjs` find the owner of a growth.
- `node scripts/crawl.mjs [--only id,id] [--json out.json]`: geometry crawl (about 20 minutes). It boots with `?audit`, visits every landmark and the opening's route, and reports by cause: stacked surfaces of different materials, terrain showing through paving, paving lips, dead-end flights, and floating or buried props. Screenshots of the worst cases go to `.shots/crawl/`. Run it after map or builder changes.
- `node scripts/stepwalk.mjs [--n 40] [--modes walk,run]`: a scripted walker crosses kerbs, road edges and paving lips with the real player controller and reports stalls (see docs/modules/movement.md). `node scripts/npcwalls.mjs [--zones forum,subura,velabrum]`: NPC contacts with static colliders per minute (`wallfix=0&navlow=0` in the query turns the fixes off for A/B).
- `node scripts/shot.mjs --scene <name> [--steps '<json>'] [--name x.png] [--browser webkit]`: boots the game headless on the real GPU, runs scripted input, saves screenshots to `.shots/`, and prints console errors and frame stats. **Always verify visual work this way and look at the PNG with the Read tool.** Steps are described at the top of the script, for example `[{"hold":"KeyW","ms":1500},{"press":"KeyV"},{"eval":"game.player.position"},{"shot":"a.png"}]`. Each run starts its own Vite server on a free port, so parallel agents don't collide.

- **The console** (`src/dev/console/`): <code>`</code> (the key left of 1) opens it over the paused game, as in Bethesda's games. `help` lists the commands: `tgm` (god mode), `tcl` (no-clip), `coc <place>`, `fight nereus`, `spawn <enemy> [n]`, `kill`/`killall`, `knock` (knock someone down: ragdoll), `munus [next|lusio]` (the games in the Colosseum: today's show, or call the next pair), `additem`, `gold`, `sethour`, `heal`, `clearbounty`, `difficulty`, `gore`, `tdo`. Scripts can call `game.console.exec('tgm on')`. Cheats last for the session only. `?fight=nereus` (or `pullus`, `auctus`) boots straight into that Ludus bout.

## Conventions (do not change without updating this file)
- **Units and axes.** Meters, with +x east, +y up and +z **south** (north is −z). The time step is fixed at 60 Hz.
- **Facing.** Character models face **+Z** in local space. A heading θ means forward is `(sin θ, 0, cos θ)` and `object.rotation.y = θ`. A camera with yaw ψ looks along `(−sin ψ, 0, −cos ψ)`. Helpers live in `src/core/math.ts`.
- **Atlas.** `src/data/atlas.ts` stores real meters. The origin is the Miliarium Aureum, and elevations are meters above sea level at ancient ground level. Convert with `src/world/coords.ts`: `toGame()` and `elevToY()` apply `WORLD_SCALE = 0.6` both horizontally and vertically. Landmark `rotation` is a compass bearing in degrees for the main facade (0 = facing north), with the facade facing −z in local space, so `rotation.y = bearingToRotationY(rotation)`. Human-scale things stay 1:1: people, doors, step risers of about 0.2 m, generic insulae with storeys of about 3 m.
- **History.** The setting is accurate to AD 113. Nothing appears that was built later (no Aurelian Walls, no Temple of Venus and Roma, no Arch of Constantine or Septimius Severus, no Baths of Caracalla or Diocletian). The fantasy is low and ambiguous: omens, curse tablets and cults, but no fireballs or dragons.
- **Controls.** The owner uses a Mac trackpad, so every mouse action also has a key: F attacks, Q blocks, R readies the weapon, E interacts, V toggles the view, C sneaks, and the arrow keys turn the camera. Bindings live in `src/core/Input.ts` (`DEFAULT_BINDINGS`). Read actions, never raw keys. `ESSENTIAL_ACTIONS` (move, jump, interact, attack, block, view, pause and so on) must never be left without a key: `sanitizeBindings` repairs saved sets on load, and the Controls screen swaps or refuses instead. Read key presses (`pressed`/`released`) in `update()`, never in `fixedUpdate()`: on a 120 Hz display half the frames have no fixed step, so presses checked there would be missed.

## Architecture rules
- `Game` (`src/core/Game.ts`) owns the renderer, scene, camera, events, input, physics, time, settings and the system list. A **System** has optional `fixedUpdate(dt)`, `update(dt, alpha)` and `lateUpdate(dt)`, plus a `priority` where lower runs first. The camera runs at 100.
- **Don't edit shared files to plug in.** Use these extension points instead:
  - Services on `Game`: `declare module '../core/Game' { interface Game { foo: Foo } }`, then assign `game.foo = …` during setup.
  - Events: `declare module '../core/Events' { interface GameEvents { 'foo:bar': {...} } }`.
  - Player state works the same way, through `interface Player` in `src/player/Player.ts`.
  - Scenes: drop a file in `src/scenes/` that default-exports a `SceneDef`. It is discovered automatically and opened with `?scene=<file>`.
- **Actors.** `src/actors/Actor.ts` is a kinematic capsule plus a visual root at the feet. Call `locomote(wish, dt)` in fixed steps; `ActorSystem` interpolates the visuals. The avatar implements `AvatarView`.
- **World content.** Register big static objects with `game.world.add(id, object, { cullDistance })` for distance culling. Use boxes or cylinders for colliders where possible (`game.physics.addBox` and friends), and trimeshes only for irregular shapes.
- **Teleports and spawns.** The city builds its buildings and their colliders lazily, near the camera and player. Never trust a ray test far from the player. Move the player only with `player.teleport()`, which primes the city at the destination first, and pick destinations with `findSafeGround()` (`src/world/safeGround.ts`), which re-checks each candidate after streaming the city in. `settleAfterTeleport()` steps the player clear if something appeared around them.
- **Climbing.** `src/player/Climb.ts` (clamber when pushing into a ledge of 0.32–0.8 m, mantle with Space up to 1.6 m; below 0.32 m `Actor`'s step-up takes the ledge in stride, at any angle, see docs/modules/movement.md) shares its ledge search with swimming (`findLedge` and `mantlePose` in `src/world/water/swim.ts`).
- **Interactables.** Use `game.interactions.add({ id, position, verb, label, interact })`.
- **Combat and the law.** The player's blows land on anyone; NPCs strike only their enemies (`CombatCore.sweepTargets`). Aim assist: `CombatSystem.assistTarget`. Crimes, guards and the arrest talk: `src/game/law.ts` (rules in `src/rpg/crime.ts`). A disposed `Actor` (`disposed`) must never touch physics again. Gore (blood, severed limbs): `src/combat/gore/` (bone-collapse plus baked pieces; never edit the shared avatar geometry).
- **Performance.** Target 60 fps in Safari and Chrome on an M-series Mac, with fewer than about 1500 draw calls and fewer than about 3M triangles visible. The owner's laptop runs hot, so cheaper is always better.
  - **Budget.** Merge static geometry per material. Use `InstancedMesh` for repeated props, share materials, and never create materials or geometries per frame. Check `stats.drawCalls` in the shot output, and use `scripts/perf.mjs` for anything bigger.
  - **The loop.** It is capped by `settings.maxFps` (default 60; `?fps=0` lifts the cap for measuring) and by `game.capFps(reason, fps)` (the title and character creation run at 30). Shadow maps re-render at about 30 Hz (`game.shadowIntervalMs`). While paused (menus, dialogue, the console) a frame is drawn only when the camera moved, once a second, or after `game.invalidate()` (settings changes call it): call it if you change the picture of a paused game some other way. An unfocused or hidden window draws nothing. Deferrable work (city streaming, avatar LOD builds) adds its time to `game.backgroundMs` and skips its big steps when another one already had the frame.
  - **Profiling.** Set `game.profiling = true` (the `?debug` overlay does) and `game.profile` holds the CPU ms per system, plus `(physics)` and `(render submit)`.
  - **Hide empty instanced meshes.** Set `visible = count > 0` on an `InstancedMesh`: three.js binds the program and uploads uniforms for an empty one before skipping it.
  - **Landmarks beyond 220 m.** These draw a baked one-mesh stand-in (`src/world/landmarks/farBake.ts`). A builder whose instanced meshes fill in at runtime (empty at build time) is skipped, so give it its own `far`.
  - **Landmarks are batched.** `buildLandmarks` moves a static landmark's meshes into the `lmbatch` BatchedMeshes (`landmarkBatch.ts`: one multi-draw per material, culled per piece by the stored-sphere walk in `src/gfx/fastCull.ts`) and gives pieces and columns coarser twins by distance (`landmarkLod.ts`, vertex clustering in `src/gfx/simplify.ts`). A landmark whose instanced meshes fill in at runtime (Colosseum, Circus) keeps its own meshes, as do transparent, non-standard or `:lod` meshes. A builder that moves or toggles a mesh after build must set `userData.noBatch` (and call `thaw(mesh)` from `src/gfx/freeze.ts` if it moves it). Each pass keeps its own draw list per batch and empty batches skip the main pass (`fastCull.ts`). Builders weld their near meshes only once they are known to stay (`build(name, { index: 'later' })`, `weldLater` in `buildLandmarks`). `?lodoff=batch,twin,chunk,precull,passlists,seal` switches the parts off for A/B runs (`procworker` the boot's procedural-texture worker).
  - **Avatar animation LOD** (`src/actors/avatar/lod.ts`, `flatSkeleton.ts`, docs/modules/avatar.md): beyond 10 m avatars use a flat bone pass (no Object3D walk for bones, the bone tree leaves the scene while nothing is carried), and beyond 25 m pose updates drop to 30/15/8 Hz by distance and visibility. Code that writes or cuts bones calls `avatar.holdFull(true)`; code that reads `bone.matrixWorld` outside the render walk calls `avatar.syncWorld()`. `?lodoff=anim` or `game.actors.lod.disabled = true` switches it off. The console's `tex` explains the texture count.
  - **Shadow LOD** (`src/gfx/shadowLod.ts`): the shadow pass is wrapped so avatars cast their low mesh beyond 12 m, baked landmarks their stand-in beyond 24 m and batched pieces their twins beyond 20 m, with the main pass untouched (it already holds its geometry when the shadow map renders). The shadow pass was 45 % of the Forum's triangles. Avatars stop casting at 28 m (the blob shadow covers them to 45 m).
  - **Frozen matrices** (`src/gfx/freeze.ts`): the scene root never updates its own matrix (`Game`), and the static top-level groups (landmarks, dressing, grass, forests, stand-ins, trees) are sealed once in the scene: their meshes get `matrixAutoUpdate = false`, their groups are frozen but watched (a group that moves is recomposed that frame, so doors and pivots keep working), and three.js's scene walk skips the whole subtree while nothing in it changed. A mesh in those groups that must move later calls `thaw(mesh)`; children added later are walked on their own.
  - **Graphics tiers** (`src/core/graphics.ts`). Settings → Display → Graphics quality: Auto (the default) reads the GPU's name before the renderer exists and writes the Low/Medium/High rows once per GPU, and `GraphicsGovernor` steps down a tier when the frame rate can't hold. Automation stays on the defaults (High) unless `?graphics=auto|low|medium|high`. The tiers also set `crowdDensity`.
  - **Memory.** Static data the GPU already has is freed after upload (`src/gfx/release.ts`): landmark meshes (all released once every landmark is built and baked; normals packed to bytes), procedural textures, sealed inscription atlas pages. Anything released must never be edited again (`needsUpdate`); runtime-edited geometry uses `DynamicDrawUsage` or `userData.keepCpu`. Measure with `node scripts/memory.mjs`. Never write an `onUpload` release callback (or any long-lived callback) as a closure inside a builder: V8 gives all closures of one function one context, which then keeps the builder's big locals alive (use `freeArray` from `release.ts`). A cache that evicts must take its reference before it trims (`head/index.ts`), and a geometry dropped without `dispose()` is never freed.
  - **Textures.** Photo sets load as KTX2/Basis (`public/textures/<set>/*.ktx2`, 2K colour) and stay compressed on the GPU; the JPEGs are the terrain's source and a fallback (`?ktx2=0`). Regenerate with `node src/gfx/textures/tools/fetch-textures.mjs --ktx2 [sets]` (needs `basisu`).
  - **Physics.** `Physics.step` drives Rapier's pipeline directly (rapier.js `World.step()` walks every collider after each step). Create and remove colliders only through the `Physics` and `World` API.
  - **NPC path failures.** These must back off, not re-plan at once: failing A* searches are the most expensive kind.
- **Interiors.** Spaces bigger on the inside (the Column's stair) are cells in src/world/interiors (docs/modules/interiors.md): built on first use under or over the world, entered through door interactions with a fade; never teleport the player into one any other way than game.interiors.enter.
- Keep modules self-contained under their own directory. Give pure logic unit tests. Match the surrounding code style: 2-space indent, single quotes, semicolons, and comment density similar to `src/core`.

## Working as a parallel agent
If you run in a git worktree, the other agents are building other modules at the same time. Stay inside the directories you were assigned. If you must touch a shared file, keep the edit tiny and mention it in your report. Run `npm install` first if `node_modules` is missing. Before finishing, run `npm run typecheck && npm test`, then commit to your branch with a descriptive message.
