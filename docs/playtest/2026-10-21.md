## Findings

1. **Frame rate dipped below 30 fps in five of fifteen minutes (minutes 3, 11, 12, 13, 14, 15; lowest 18 at minute 13).** Minutes 3 and 11 to 15 are the dips, and the run was at 60 fps in between. The bot kept making progress (trips rose from 56 to 72), so this is not the frozen state seen in the 2026-10-14 run. Cause not known. Geometry and object counts stayed in the range of earlier minutes. The host was not idle: the 2am and 3am nightly jobs overlapped this run, and the machine has 32 cores at a load average of about 7. Possible contention from those jobs is untested. Log lines 2128, 2138 to 2141, 2143.
2. **Bot stuck counter vs NPC unstick log disagree.** The per-minute "stuck" count (the bot's own trip-progress counter, `soak.mjs` line 148) reached 19. The NPC unstick report printed "0 total (0 logged)" (log line 2144), and `/tmp/stuck-2026-10-21.json` contains `total: 0`. The two counters measure different things, so this may not be a bug, but it is worth confirming which one is right. This matches finding 2 of the 2026-10-14 playtest, which is still open.
3. **Deaths: 3, all recovered.** Rescues logged at minute 4 to 5 (player died at 34,8,20), minute 9 (112,8,14) and minute 14 (40,8,65). No unrecovered deaths.
4. **Environment noise, not a game finding.** The log holds 2124 `file watcher error: ENOSPC: System limit for number of file watchers reached` lines from the Vite dev server (inotify limit on the host). They did not stop the run or cause a page error. The host's inotify limit could be raised, but the owner has no non-interactive sudo, so that is for the owner to decide.

Errors: `grep -i error|warn|uncaught` returned only the ENOSPC watcher lines. Page errors: 0.
