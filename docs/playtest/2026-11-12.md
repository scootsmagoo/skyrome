## Findings

1. **FPS dipped below 30 in four minutes** (headless bot run, so not a device measurement): minute 5 at 29 fps, minute 8 at 28, minute 10 at 28, minute 11 at 25. Log lines: `minute  5: … 29 fps …`, `minute  8: … 28 fps …`, `minute 10: … 28 fps …`, `minute 11: … 25 fps …`. The run has no per-system profile, so the cause is not identified. Other agents' processes on the host may have contributed.
2. **Stuck counter vs. unstick counter disagree.** The per-minute "stuck" counter reached 13 trips, but the soak's final summary reports `NPC unsticks: 0 total (0 logged, 0.0 per minute)` and the `--stuck` file `/tmp/stuck-2026-11-12.json` has `"total": 0, "log": []`. The two counters are not reconciled by the script output. This needs a look at what the per-minute stuck count measures (log line 19 and the summary block at the end of the log).
3. **Deaths: 3, all recovered** by the Aesculapian rescue (log lines 6, 12, 18: "player died … rescued (1/2/3 so far)"). Death at minute 14 was at y=21, the others at ground level.
4. **Environment noise, not a game error:** 2,124 lines `file watcher error: ENOSPC: System limit for number of file watchers reached`. This is the host's inotify limit hit by the dev server's file watcher. The soak still passed. Raising `fs.inotify.max_user_watches` on the host would remove the noise; that needs the owner's sudo.
