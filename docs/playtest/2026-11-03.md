## Findings

1. **Vite file-watcher limit hit (environment, not game code).** The log has 2112 lines of `file watcher error: ENOSPC: System limit for number of file watchers reached, watch '/home/murphy/.hermes/cache/scratch/skyrome/...'`. The dev server cannot watch files because the host's inotify watch limit is exhausted. The game ran regardless and the bot reported no errors, but hot reload is broken on this host. Fix belongs to the host: raise `fs.inotify.max_user_watches` (needs sudo, so the owner has to run it).
2. **Stuck counter rose to 17 at minute 15, but the stuck file is empty.** The `--stuck` JSON at `/tmp/stuck-2026-11-03.json` reads `total: 0, log: []`, and the summary line says `NPC unsticks: 0 total`. The per-minute `stuck` figure in the samples (1 → 17) appears to count something other than logged NPC unsticks. Not reconciled: I did not read the soak source to find out what it counts. Worth a look before trusting either number.
3. **Frame rate dipped at minute 5 (41 fps) and minute 15 (54 fps).** Both stay above 30, so no dip below the 30 fps threshold. Minute 5 is the death-and-rescue minute, and the dip was not investigated.
4. **Deaths: 3, all recovered.** The bot killed the player at minutes 4, 9 and 14 (`--die-every 5`). Each was followed by a rescue (`rescued (1/2/3 so far)`). No respawn failures appear in the log.

No page errors, no `Uncaught` lines, no crash. The grep for `error` and `warn` matched only finding 1.
